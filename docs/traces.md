# Trace import contract v1/v2/v3

`jevopt traces import <file> --repo <target> --state-dir <external-state>` accepts a JSON array or JSONL (one object per nonblank line). The strict record schema is in [trace-v1.schema.json](../schemas/trace-v1.schema.json). Every field is required; unknown fields and duplicate JSON keys are errors. Version mismatch, invalid dates, noninteger/negative/out-of-range counts, unknown candidates, unsafe labels, extra payload fields and inconsistent option sets fail the entire import. No partial rows survive a rejected import.

Only current STATIC_CANDIDATE IDs are eligible. IDs are obtained from `candidates`; fixture examples correspond to the supplied synthetic agent. Static fingerprints and primitive are derived from the scan, never accepted from a trace. Source changes mark existing samples stale and exclude them from replay/recommendation metrics. Option drift requires a separate external state directory or explicit purge/reimport.

Inputs are explicit regular files with no symlink components, under the same read boundary and sensitive-file restrictions as source. Limit: 2 MB, at most 10,000 input records, JSON depth 12, strings 256 characters, options 2–32, option labels 1–24 characters, model/event labels at most 64 characters. Strict labels use letters/digits/dot/underscore/hyphen, reject detected credentials/paths/emails/secret-like strings, and are not arbitrary prose. Event IDs are hashed with candidate IDs; raw IDs are never persisted. They are idempotency keys: repeating an identical event deduplicates; changing its fields rejects the transaction. Use pseudonymous identifiers, not customer/account names. No sanitizer guarantees removal of all sensitive categorical data.

v3 is the sole real-replay format. It deliberately imports a bounded, user-approved Class-2 `sanitizedState`, atomic question instructions and typed criterion descriptions, pin `jevModel: jev-1.13.0`, and a source-evidence fingerprint. This is **not** a raw prompt/payload capture: secrets, auth markers, paths, unsafe IDs, deep/oversized fields and unknown keys fail closed. This explicit sanitized state is persisted only in the external state database, contributes to replay freshness/fingerprints, and is removed by `purge --confirm`. v1/v2 remain readable but never support remote replay.

`config` reads validated privacy settings. Only analyzer none, telemetry off, raw traces off, symlinks off and auto-apply off are supported. `purge --confirm` deletes samples/replays, preserving config/schema. It requests SQLite secure-delete, but is not forensic erasure of backups, filesystem snapshots or storage media. Read/status commands may apply the one-time schema migration on first access.
